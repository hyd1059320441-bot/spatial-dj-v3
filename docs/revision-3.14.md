# V3.14 — 全屋补光与自动演奏页面同步

房间主光及新增补光组成两束对向 800 lux 中性照明，俯角 40°，
水平角 45°/225°，覆盖四面墙及地板。保留两束公共扫射聚光，共四个
实际光源，无阴影贴图。环境光由 +3 升到 +4 EV（强度两倍）；
墙面、地板、顶棚的 PBR 基色分别提亮为 #788793、#596B78、#627581。
顶棚保留三块可见灯板，灯板本身不计作实际光源。

曾尝试四盏大范围顶灯及两盏补光，但真机播放时出现 GPU_NO_RETIRE，
导致 Spatial Runtime 重启。缩小半径、换成顶棚聚光也未解决。
最终采用较少、覆盖方向明确的平行光，弃用不稳定的顶灯配置。

自动演奏此前由 AutoScore.emptySession() 载入旧的 DropOnly 默认工程，
导致界面与默认完整编曲不一致。现在载入 FullSong，明确选中 Drop 完成六次录音；
随后按每个 AutoSection 的显式 SongPart 显示当前段落。状态快照使用实际播放片段
的音符数，空轨显示「本段休止」。Outro 没有旋律时，反馈转到实际有音符的底鼓轨。
录制所得工程与播放片段仍独立，切段不会改写已提交音符，取消和后台恢复维持原逻辑。

源乐谱、APK 内置乐谱、生成器的段落元数据与 100% 总音量同步。
外部 UiMusicPerformance 驱动改为在完整编曲页面选择 Drop，监听用「试听本段」，
通过音轨按钮判断演奏页是否打开，避免把工具箱的「清空」误判为演奏页。

验证覆盖：原生光源组件、四面墙/地板的入射方向、动画与
退出回收；自动演奏模式、段落、各轨音符数、重复乐段、存储恢复、PCM 分块一致性、
原声库完整编排；真机自动演奏控件布局与文字溢出检查。
本轮不执行会另存音乐的外部苏珊娜全流程。实际亮度观感由用户佩戴确认；
没有截图验证，暂停的物理指尖延迟测试保持暂停。
结果见 [交付记录](../artifacts/2026-10-30-v3.14/delivery.md)。
